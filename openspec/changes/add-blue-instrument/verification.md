## Measurements

The optimized Linux benchmark rendered ten minutes of audio on an AMD EPYC 9V74 with GCC 14.2.0 at 48 kHz. Sixteen held voices used a wavetable, FM pair and granular source, three filters, delay and stereo room sends. The 128-frame blocks had a 2.67 ms period and a 1.87 ms p99 budget. Measured p99 was **0.8538 ms** with zero silent or nonfinite blocks. The Linux process reported 9,216 KiB peak resident memory. This measures DSP execution offline. Real-device dropouts, callback scheduling and headset headroom require their own recordings.

Unit coverage on Linux combines exact executable-line counts from GCC, Lua debug line hooks and Node/V8. It inventories first-party host and engine C, handwritten browser JS and factory Lua, excluding tests, dependencies and compiler-generated glue. This configuration covered 2,685 of 2,773 lines (96.83%). The smallest group result was 95.71% for the desktop adapter. Each group and the weighted total must reach 95% before rounding. Native builds and audible E2E run separately on Windows and macOS. The published GCC counters describe the Linux configuration. [C inventory](../../../tests/coverage.py) · [Combined gate](../../../tests/coverage_total.py)

All five reference scores passed native/Wasm RMS and occupied-band limits. Calibration also passed the per-sample error bound. Four 20-second listening WAVs measured between −23.01 and −22.99 LUFS. The panel artifact contains the measured levels and a blank sheet for three independent assessments of movement, clarity and control response. The target is a median of four out of five on each attribute for each patch. Listening scores and comparisons with Absynth require listening trials. ## On-device record

Serve the candidate's static artifact over HTTPS. Record the commit, Quest system and browser versions, controller model, audio output, device sample rate and block size. Open the instrument with `?voices=8` to select the headset voice budget. Start audio in the flat instrument, enter immersive mode, trigger a held note, grip and move its layer, and turn through 180°. Record the stereo result, any interruptions and whether the trigger releases after controller disconnection and session exit. Repeat the performance trial with the specified eight-voice headset profile. Record p99 DSP time, memory high-water mark and discontinuities in ten minutes of output. On Linux, `python tests/profile.py build/bin/blue_benchmark evidence` captures the optimized ten-minute baseline, a 30-second reload and parameter-flood soak, both WAVs, their frame traces and machine information. The manual Actions workflow publishes the same evidence. Keep the physical results with the exact package and the three listening sheets before tagging.
